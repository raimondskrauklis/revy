## P0 — Stable identity

| Severity | Area | Finding |
|:---|:---|:---|
| critical | general plan | H1 called for a **stable claim key**. RH-Q4 locked that key as **start_line**. `test_compute_fingerprint_differs_by_start_line` already treats a line change as a new identity. P1 then closes an identity that is absent after a successful compare. A one-line insert above `eval` is the findings experiment **pass** case (`eval` still open) and the **fail** case for Outdated-as-resolved. Under RH-Q4 + H2, the old line is absent → group `resolved`, the new line is a **new** raised identity. That is the same lie as Outdated, implemented in the DB. **Lock before execution:** either start_line is an **attribute** (update in place; identity is something that survives drift), or H2 must **not** close on mere absence when a nearby same-path+category finding exists, or the eval gate is dropped. The three cannot stand together. |
| high | codebase | After dropping title, identity is path + category + start_line. Two different bugs in one file, same category, same line become **one group** (`uq_github_finding_groups_pr_fingerprint`). Findings list PAT and innerHTML both at **line 4** (possibly different files — unknown). Execution needs a collision policy (keep separate via extra claim key, or document “one finding per line”). File+category peer supersede is retired with no replacement except this coarser merge. |
| high | general plan | P0 “match existing rows via old D10 hash for one generation” only hits when the **current finding title** still hashes to the stored fingerprint. The motivating INFO→CRITICAL **title rewrite** uses a different title, so old D10(current title) **misses**. Continuity for that case is attribute lookup (path + category + start_line from `github_findings`) or a fingerprint rewrite migration. The plan parks backfill as “calibration only.” Groups do not store `start_line`; rewrite must join latest findings. Collision on rewrite violates `uq_github_finding_groups_pr_fingerprint`. Latest Alembic head is `0034` — any rewrite is handwritten, not `--autogenerate`. |
| medium | general plan | P0 has no Files / test-path deliverables. Minimum new tests: title+severity rewrite stays one group; two titles same line collide or stay distinct per lock; `_mark_superseded_peers` is gone; old D10 cutover. Existing tests in `test_github_finding_reconcile.py` assert current D10 + supersede. |
| low | findings | `compute_fingerprint` docstring still says “Deploy supersede pass in 0026 per D10-M” — doc-sync after P0, not blocking. |
